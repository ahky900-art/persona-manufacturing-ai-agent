핵심 설계 원칙

  • Persona는 검토 우선순위·질문을 제공하며 안전등급을 결정하지 않습니다.
  • 사고사례 태깅은 사고 후 서술의 검색·분류이며 사고 발생확률이 아닙니다.
  • 설비 열화와 작업자 안전은 별도 위험 체계로 다룹니다.
  • 핵심 통제 실패(예: 정비 중 LOTO 미확인)는 종합점수와 별개로 확인합니다.

설비별 임계값 설정 및 경보 시뮬레이션

경고·위험 기준과 현재값은 현장 승인값을 직접 입력합니다. 값이 비어 있으면 경보 판정을 하지 않으며, 이 화면은 실제 센서와 연결된 실시간 감시가 아닙니다. 설정은 현재 브라우저에 저장됩니다.

임계값과 현재값을 입력하면 상태가 표시됩니다.
중요: 이 그래프의 KOSHA 사고사례는 위험 시나리오의 근거이며 설비별 사고확률이 아닙니다. 내화물 손상 메커니즘은 Refractory 온톨로지의 공학적 가설입니다. 경보 기준은 설비 설계값·제조사 기준·현장 위험성평가 및 승인된 운전절차로 검증해야 합니다.

① Hugging Face 원천 데이터

Nemotron-Personas-Korea의 직무·전문성 관련 필드를 분류 입력으로 사용합니다. 실제 스키마 버전과 누락 필드를 확인한 뒤 사용해야 합니다.

주의: Persona → 산재 유형 → 산업현장 Risk의 엣지는 곧바로 인과관계나 사고확률을 뜻하지 않습니다. Persona는 분석 관점이고, 산재-설비 연결은 실제 공정·작업 조건이 확인될 때만 유효한 시나리오로 취급합니다. 설비 손상 위험과 인명 안전 위험도 별도 평가합니다.

검증·출처·제한

필수 검증

  • Persona 역할: 산업안전·생산·정비 전문가 라벨 대비 Macro-F1, Precision, Recall
  • 사고 포커스: KOSHA 사례 전문가 다중라벨 대비 태깅 정확도·누락률
  • 설비 위험: 정상운전·비사고 데이터 포함 PR-AUC, Recall, 오경보율, 치명위험 누락률
  • 운영 효용: 야간 알림 수, 중복경보율, 확인시간, 조치 리드타임
