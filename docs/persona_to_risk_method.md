# 페르소나 → 사고 포커스 → 제조 현장 위험 감지

## 1. 설계 원칙
합성 페르소나는 근로자 개인의 성격·능력·사고확률을 판정하는 데 사용하지 않는다. 직무·전문성 서술을 위험 검토 관점(review lens)에 매핑한다. 실제 위험 판정은 설비·공정 상태, 작업·에너지 격리, 검사·센서 데이터로 수행한다.

## 2. Nemotron 필드 사용 기준
| 필드 | 분류 사용 | 기준 |
|---|---|---|
| occupation | 핵심, 가중치 4 | 직업명과 직무 사전 매칭 |
| professional_persona | 핵심, 가중치 4 | 주요 업무분야·역량·업무태도 키워드 |
| skills_and_expertise_list | 핵심, 가중치 3 | 명시적 기술·전문성 |

| OCEAN 5개 | 분류 제외 | 안전 역할·사고 포커스를 직접 결정하지 않음 |

기본 Hugging Face 데이터는 26개 필드로, 7개 페르소나 서술과 6개 속성 필드, 인구통계·지역 필드 및 UUID를 포함한다. 기본 스키마에는 OCEAN 점수가 없다. NVIDIA Extended 설명은 51개 필드와 OCEAN 5개 문자열 속성을 제공한다고 명시한다. Extended의 개인·건강·인구통계 속성은 이 분류에서 제외한다.

## 4. 사고사례 포커스
KOSHA 원본 필드를 보존한다: BBSCTT_SJ_NM(제목), BBSCTT_CN(발생 개요), DSSTR_INDUCT_FCTR_CN(발생 원인), RSKNSS_DCRS_CNTRPLN_CN(예방대책). 네 필드에서 위험 키워드를 다중 태깅한다: 끼임/협착, 추락, 충돌/낙하, 화재/폭발/화상, 질식/중독, 감전/전기, 근골격/수작업. 결과는 사례 검색과 검토 우선순위이며 사고확률 추정이 아니다.

## 6. 설비 위험과 인명 안전 위험 분리
설비 위험(용손·침식·균열·박락·쉘 핫스팟)과 작업자 위험(끼임·추락·충돌·화상·질식·감전)을 별도 평가한다. 정비 중 LOTO 미확인은 종합 점수와 무관한 별도 핵심통제 경보다. 두 종류 위험을 임의로 합산하지 않는다.

## 7. 온톨로지
PersonaRecord → WorkFunctionRole → ReviewLens → AccidentFocus → Hazard → Equipment → ProcessCondition → DamageMechanism → DamageEvent → MonitoringSignal → Alert → ControlAction.
각 엣지에는 source, evidence, confidence, condition, valid_time, review_status를 기록한다. 문헌 가설·저장소 가설·현장 검증 관계를 구분한다.

## 8. 검증
페르소나 역할은 전문가 라벨과 Macro-F1/Precision/Recall, 사고 포커스는 KOSHA 전문가 다중라벨과 Macro-F1/누락률, 설비 위험은 정상운전·비사고 데이터 포함 PR-AUC/Recall/오경보율/치명위험 누락률로 평가한다. 임계치는 사업장 위험성평가·설비기준·센서 신뢰도로 보정 전까지 데모값이다.

## 9. 한계
합성 페르소나는 실제 작업자의 성격·행동·숙련도 데이터가 아니다. 사고사례는 사고 후 서술이며 정상상태 분포나 사고확률을 제공하지 않는다. 설비 메커니즘과 센서 연결은 검증 전 가설이다. 작업중지·재가동 등 안전 중요 결정은 현장 책임자 승인 절차를 따른다.
